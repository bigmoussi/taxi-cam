The native probe intentionally uses a narrow ReShade/ImGui ABI boundary. Windows GNU and MSVC C++ ABIs are **not generally compatible**. ReShade methods returning structures, even an eight-byte resource handle, use incompatible return conventions. Some ImGui structure returns also differ.

Run `abi/validate.ps1` after dependencies are bootstrapped. It compiles wrappers against the pinned, unmodified public headers with the same Clang binary for both Windows targets, then compares function assembly. The wrappers cover the selected virtual call slots, handle arguments, callback parameters, ImGui table calls including varargs, and referenced record layouts. Negative controls must detect the known incompatible returns. A source call inventory rejects additions to the boundary until reviewed.

The two structure-return getters needed to resolve an application RTV use `native_bridge.cpp`, compiled separately for `x86_64-pc-windows-msvc`. This freestanding object calls the native MSVC interface and exposes a scalar/pointer-only C boundary to the add-on. The gate builds `build/abi/native_bridge.obj`; the add-on build must link that object. The bridge includes no STL and cannot be compiled accidentally with the GNU target.

The files in `shims/` supply only fundamental Windows x64 type and C function declarations for the **compile-only probes and freestanding bridge**. They are not runtime implementations and must never be included by the main add-on build. No ABI probe is linked or executed. Full native validation must additionally load the actual installed ReShade in an isolated test process; this assembly check does not establish simulator rendering behavior.
