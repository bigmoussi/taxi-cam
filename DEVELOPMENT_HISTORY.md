## Build and validate

From the repository root in PowerShell:

```powershell
.\build.ps1 -Bootstrap -Validate -ReShadeDll 'C:\XboxGames\Microsoft Flight Simulator 2024\Content\dxgi.dll'
.\smoke-test.ps1 -ReShadeDll 'C:\XboxGames\Microsoft Flight Simulator 2024\Content\dxgi.dll'
```

`bootstrap.ps1` downloads pinned ReShade 6.8.0, its matching ImGui headers, and a portable LLVM-MinGW compiler into the ignored `build/deps` directory. Archive SHA256 values are checked against `dependencies.json`. It does not install system software. ReShade and ImGui licenses remain in those source archives; the generated add-on includes their header code.

The build treats warnings in project code as errors. Every build runs the [ABI checks](abi/README.md). The add-on uses only the verified scalar/pointer/void C++ boundary. Two structure-return getters go through a separately compiled Microsoft-ABI object with a C interface; a general MinGW/MSVC compatibility assumption would be incorrect.

`-Validate` requires the existing ReShade DLL for the actual PFD adapter test. It runs camera lifecycle, resize/warm-up, memory/code guards, queue ordering, capture/replay, composition and PFD-state tests, plus the calibration and [offscreen GPU hosts](validation/README.md) on hardware and WARP. Pixel readback is test-only. The scene pipeline keeps capture, composition and PFD delivery on the GPU.

The smoke test copies the existing ReShade DLL and this add-on into an isolated test directory, runs the GPU host there, and requires actual registration, device creation/destruction and unload messages. It leaves the simulator installation untouched.

Outputs are under `build/`:

- `taxi-camera-native.addon64`: native add-on.
- `validation-result.json`: binary hash, ABI/boundary results and GPU results.
- `smoke-result.json`: exact add-on/ReShade hashes and lifecycle result.
- `reshade-smoke/ReShade.log`: isolated host evidence.

No MSFS SDK, Docker, WASM build or TypeScript build is needed for this standalone tool. It does not change the A380 build graph.

Calibration stops recording on deselection, a lost/replaced selected resource, device loss or allocation failure. Each batch records five rectangles. A new device Present callback or 50 ms of monotonic elapsed time refreshes the quota; manually enabling calibration starts a fresh session. Exhaustion keeps the selection and enable state, forwards the original draws/copies unchanged, and reports throttled events through counters and log messages at most once every five seconds per enable session. The Present count and timed-reset count help distinguish advancing presentation from a stationary counter; a timed reset can also occur during a slow frame. Later instrument drawing can reveal normal PFD symbology while calibration is throttled. The user confirmed the normal PFD test works in 0.5; deliberately exhausting its new quota is a separate unperformed live check.

## Implementation boundaries

The add-on observes non-depth 2D textures between 32 and 16384 pixels per dimension, including other formats, arrays, mip chains, shared resources, copy-only resources and native render passes. It records SRV registrations and copy source/destination relationships. Observation does not imply safe write support, and an SRV registration does not prove that a texture is currently sampled.

RTV calibration supports valid mip chains on single-layer, single-sample RGBA/BGRA8 textures. It uses the actual bound mip index and typed format for its owned RTV, with clear dimensions scaled to that mip. Each bound mip must be at least 32 × 32; all five mips of the observed 768 × 1024 display textures meet this bound. The RTV path forwards supported direct/indexed draws with exactly one compatible target, then records five rectangle clears through the owned descriptor. Copy calibration remains restricted to single-mip textures; it forwards supported whole-resource or texture-to-texture copies once, then copies five immutable color tiles into the upper region while the destination remains in `COPY_DEST`. No application resource transition or pipeline-state change is added.

Buffer-to-texture uploads and resolves are observational only. ReShade 6.8's upload event omits the original source-box origin and row pitch, so replaying it is not generally lossless. Texture-to-texture events preserve the two subresources, source box and destination coordinates; native replay preserves those fields, including a null source box. Calibration is excluded inside native render passes; a later supported copy after a pass ends establishes a fresh write opportunity. The immutable upload cache is bounded to 16 size/format entries and 128 MiB and retained through selection changes. At queue destruction, a checked native fence waits up to 30 seconds for outstanding work. An unverified drain retains its upload references until process exit instead of freeing GPU-referenced storage. Recording does not add GPU waits.

The pinned ReShade barrier callback omits native split/layout details, so it is used only to invalidate tracking. Native render passes, indirect operations, bundles and sparse resources are excluded from calibration. The real binding is resolved through ReShade's internal descriptor mapping at bind time because RTV descriptor copies do not emit a public view event. Using an owned RTV also avoids clearing through an application descriptor that has subsequently been reused.

The candidate list provides no arbitrary texture preview. The scene pipeline separately admits only lifecycle-matched owned-camera copies, with explicit recording and queue-completion checks. The probe tracks at most 16384 candidate resources and 16384 RTV registrations. Calibration overhead is diagnostic overhead, not a camera performance benchmark.

## GPU capture and two-source compositor

[CameraCompositorD3D12](src/camera_compositor_d3d12.hpp) combines two explicitly supplied GPU textures into one owned **768 × 763 RGBA8_UNORM** texture: **255 nose-view rows**, a **four-row black divider**, then **504 tail-view rows**. One fullscreen triangle samples the two inputs. The output is opaque; sRGB SRVs decode to linear RGB. Each feed fills its assigned region.

The caller supplies an open, private direct command list and each input's exact mip-zero state. Recording restores those states and leaves the output in `COPY_SOURCE`. Shader compilation, pipeline/resource allocation and the output RTV occur during initialization; input SRVs change only when resources or formats change. Recording has no CPU frame upload, readback or per-frame descriptor allocation. The caller must synchronize camera producers, composition and output copies, and establish GPU completion before changing inputs or releasing resources. This does not establish simulator resource ownership or scheduling.

The validation command above builds [compositor_main.cpp](validation/compositor_main.cpp), runs it on hardware and WARP, and saves `compositorDefaultDevice` / `compositorWarp` in `build/validation-result.json`. The host creates source colors and gradients on the GPU, records changed frames, copies the upper area into a sentinel-filled PFD texture, and reads pixels back only for testing.

Both hardware and WARP independently pass **six frames and 4,718,592 pixel checks**, including **18,432 exact divider pixels**, **1,202,688 exactly preserved lower-area pixels**, and **19 refusal checks**. Tests cover different input dimensions, RGBA/BGRA formats, typeless resources with sRGB SRVs, a mipped input, restored input states, multisample rejection and non-direct-list rejection. Filtered RGB has a two-code-value tolerance for GPU sampling/rounding; alpha, divider and lower PFD pixels are exact. The D3D12 debug layer is unavailable on this machine. Shader compilations stay at two and descriptor writes at seven across three input pairs; these checks are not a frame-rate benchmark.

Source 0.7 links the compositor into the add-on. A generation-checked handoff matches the engine's borrowed output member to real ReShade resource lifecycle/copy events. Supported copies produce owned GPU snapshots; native queue observation supplies a post-submission fence point, and recording generations prevent premature reuse. Completed paired snapshots are composed into a stable GPU buffer and drawn over the selected PFD through the validated state adapter. Stop, restart, owner replacement and stale resource identities invalidate admission. This implementation has passed hardware/WARP and actual-ReShade tests; camera scene contents in MSFS remain to be checked.

Earlier experiments cloned one validated camera pose for both views.
